# VulnScout

VulnScout is a domain-specific chatbot for software vulnerability intelligence. You ask about a package and version (for example, "Is log4j-core 2.14.1 affected by anything I should patch first?"). It answers with the CVEs that affect that version, whether they are being exploited in the wild, how likely exploitation is, and which version fixes them. Every claim cites the record it came from.

General-purpose LLMs are unreliable here because vulnerability data changes daily and version-range matching is easy to get wrong. VulnScout lets the LLM do the language work: it interprets the question and explains the result. Deterministic tools do the lookups and version comparisons against authoritative live sources:

- [NVD](https://nvd.nist.gov/developers/vulnerabilities) (CVE records, CVSS, CPE configurations)
- [CISA KEV](https://www.cisa.gov/known-exploited-vulnerabilities-catalog) (known exploited vulnerabilities)
- [FIRST EPSS](https://www.first.org/epss/) (exploitation probability)
- [OSV](https://osv.dev/) and [CVE List V5](https://github.com/CVEProject/cvelistV5) (package-level affected version ranges)

This is the final project for INFO 7375 *Semantic Intelligence in LLM* (Northeastern University, Seattle, Fall 2026).

## Quick start

```
python -m venv .venv
.venv\Scripts\activate            # source .venv/bin/activate on Linux/macOS
pip install -r requirements.txt
python -m vulnscout.cli log4j-core 2.14.1          # deterministic core only, no LLM
python -m vulnscout.chat                           # chat with the agent (Claude)
python -m vulnscout.knowledge --build              # one-time: download MITRE CWE + ATT&CK and build the concept index
python -m vulnscout.web                            # web chat UI at http://127.0.0.1:7860
pytest                            # offline tests; VULNSCOUT_LIVE=1 pytest tests/test_live.py for the NVD cross-check
```

The chat agent calls Claude through the Anthropic SDK. It picks up an `ant auth login` profile or `ANTHROPIC_API_KEY`.

Responses are cached for a day under `data/cache/`. Without an NVD API key, NVD allows 5 requests per 30 seconds. With a key in `NVD_API_KEY`, it allows 50.

## Repository layout

```
vulnscout/                deterministic core (no LLM)
  versions.py             version ordering; NVD CPE, OSV and CNA range semantics
  resolver.py             multi-source verdict with provenance and confidence (contribution 1)
  ranker.py               KEV > EPSS > CVSS prioritization with reasons (contribution 2)
  pipeline.py             product + version -> ranked findings
  sources/                NVD, CVE Services (CNA), OSV, CISA KEV, FIRST EPSS clients
  catalog.py              verifies product identifiers (NVD CPE dictionary, deps.dev)
  tools.py                tool schemas and implementations exposed to the model
  agent.py                tool-use loop with a pluggable model backend (Claude now, open-weight model next)
  chat.py                 terminal chat
  products.py             seed product table for the CLI and tests
  cli.py                  command-line check
tests/                    unit tests on saved API responses, plus a live cross-check against NVD
phase1/                   Phase 1 proposal (LaTeX, CVPR template)
  cvpr.tex                main document
  egbib.bib               references
  fig/                    figures; cover.png is generated by make_cover.py
  make_cover.py           builds the cover figure from real NVD/KEV/EPSS data for log4j-core 2.14.1
  Phase1_YuanhaoCao.pdf   compiled proposal
```
